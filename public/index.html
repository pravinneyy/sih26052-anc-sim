    Two problems, not one

    The problem statement says "ANC", but it describes two jobs with latency budgets three orders of magnitude apart. That gap decides the whole architecture.

    Select a block to see what it does.

    Shared state detector

    Short-term energy against a slow background estimate. Classifies the acoustic state as normal, non-stationary or transient, and gates both paths.

    It runs on the reference microphone, not the boom mic — so shouting into the boom mic cannot trigger transient protection.

    What happens when the headset shifts

    FxLMS depends on a model of the speaker-to-error-mic path. Move the headset, change the seal, change the ear, and that model is wrong.

    What we have shown, and what we have not

    Round 1 covers the cancellation path in simulation. The enhancement path and all hardware are still ahead of us.

    Enhancement preview — illustrative, not trained

    Panel 1 labels a Causal GRU mask on the 16 kHz enhancement lane. This panel is a hand-written gain heuristic standing in for that model, so the shape of the idea is visible before a real network exists.

    Not a neural network. Each of 6 broad bands (the real design uses 22 Bark bands) gets a gain from a fast/slow energy-ratio tracker — the same exponential-tracking shape as the state detector in js/sim.js, not a trained mask. It is a placeholder for the shape of the idea, not a performance claim.

    Why this is here at all

    The problem statement is an AI/ML noise-suppression system. Round 1 has no trained model yet — training one needs the dataset pipeline in the roadmap's later phases — but showing nothing where the enhancement lane should be reads as an afterthought. This panel shows the mechanism a learned mask would sit inside: per-band gain, estimated from local signal statistics, applied and resynthesised.
